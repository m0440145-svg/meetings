# اختبار النسخ والاسترجاع

## تحقق محلي قابل لإعادة التنفيذ
شغّل `npm ci --ignore-scripts` ثم `node --test tests/lifecycle.test.cjs`.
ينشئ الاختبار قاعدة منفصلة، ينفذ الدورة، يأخذ dumpDataDir، يسترجع إلى قاعدة ثانية، ويقارن البيانات والتدقيق والصلاحيات. بياناته اصطناعية داخل الاختبار فقط. لا يتصل بالإنتاج.

## قبول الاسترجاع الحقيقي قبل النشر
1. أوقف التغييرات مؤقتًا أو حدد نقطة اتساق موثقة.
2. خذ نسخة PostgreSQL تشمل public وmeeting_private وبيانات Auth والسياسات والدوال والتسلسلات حسب آلية النسخ المعتمدة لدى Supabase؛ احفظها مشفرة خارج خدمة الواجهة.
3. انسخ كائنات meeting-files وsignatures مع المسارات والأحجام وSHA-256 في manifest. خزّن مفاتيح الوصول في مدير أسرار، لا في المستودع أو ملف الواجهة.
4. استعد إلى مشروع اختبار مختلف تمامًا. لا تسترجع فوق الإنتاج ولا تعكس ترحيلًا بحذف جداول.
5. قارن أعداد السجلات والمفاتيح المرجعية وأعلى أرقام التسلسلات وبصمات المحاضر وسلسلة التدقيق.
6. قارن كل كائن Storage بالبصمة والأحجام وتحقق من الروابط والسياسات بحساب عضو مخول وآخر غير مخول.
7. تحقق من Auth وتسجيل الدخول وحالات المحاضر المغلقة وإعادة اختبار التصويت المكرر وإغلاق الاقتراع.
8. سجل وقت بداية النسخ ونقطة النسخة ووقت اكتمال الاسترجاع والفقد الفعلي إن وجد؛ لا تعتمد RTO/RPO قبل قياسهما.

لم يُنفّذ هذا القبول على مشروع مستضاف حتى الآن. اختبار PGlite دليل على آلية البيانات داخل الاختبار، وليس بديلًا عن استرجاع ملفات Supabase وحساباته.
