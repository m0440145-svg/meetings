# تقرير الفحص الشامل للمنصة

تاريخ الفحص: 28 أكتوبر 2026. نطاقه: واجهة المنصة (ملفات JavaScript الثابتة)، وقاعدة البيانات (الترحيلات)، والنشر على GitHub Pages.
المنصة نظام اجتماعات وحوكمة وقرارات، وليست بثّ فيديو؛ فلا توجد فيها خدمات بثّ أو وسائط يمكن اختبارها.

## 1) ما نُفِّذ فعلًا
| المجال | ما تم | النتيجة |
|---|---|---|
| قاعدة البيانات | إعادة بناء قاعدة تجريبية (PGlite) وتطبيق الترحيلات 011 و012، وتجربة `add_committee` و`import_members` | مرّ: إنشاء جهة، رفض الاسم المكرر والنوع الخاطئ، استيراد (created/exists/error)، حد 500 صف، رفض غير المدير |
| الوصولية | فحص آلي لـDOM الصفحة | وُجدت 3 أزرار أيقونية بلا اسم، و21 حقلًا بلا تسمية، و3 نوافذ بلا اسم → أُصلحت بـ`a11y.js` (0 متبقٍ في الفحص نفسه) |
| الأداء | قياس حجم وزمن 30 ملفًا من الموقع الحي | الحجم الإجمالي ≈ 174 كيلوبايت مضغوطًا (جيد). المشكلة في التسلسل: الملفات تُحمَّل واحدًا بعد الآخر وزمن كل طلب ≈ 0.4 ث، أي نحو 12 ث في البداية الباردة → أُضيف `preload` للتنزيل المتوازي |
| الأمان | بحث عن مفاتيح سرية، وفحص CSP وSRI وروابط `_blank` | لا `service_role` في الواجهة (المفتاح الظاهر publishable وهو مخصص للعلن). SRI مفعّل لمكتبة supabase. أُضيف `rel=noopener` لرابط الاجتماع |
| الكونسول | فحص أخطاء الصفحة بلا جلسة | 401 من `rpc/is_admin` بلا جلسة → أُصلح بفحص الجلسة أولًا |

## 2) لم يُنفَّذ (وسبب ذلك)
- **اختبار أحمال بمستخدمين حقيقيين:** يحتاج نسخة تجريبية من Supabase وحسابات اختبار. لا يُجرى على الإنتاج. المطلوب: k6 أو Artillery على مشروع Staging.
- **اختبار المتصفحات والأجهزة (Safari وFirefox والجوال الفعلي):** لم يتوفر لدي غير متصفح واحد. الموصى به: BrowserStack أو الاختبار اليدوي بالقائمة أدناه.
- **التكامل مع مزودي الإشعارات:** دالة `process-delivery-jobs` لم تُنشر بعد، وتحتاج مفاتيح Resend/واتساب/SMS وسرّ `CRON_SECRET`.
- **اختبار الواجهة بحساب حقيقي:** جلسة الدخول لم تكن مفتوحة؛ الاختبار اليدوي مذكور في `خطوات-الاختبار.md`.
- **اختبار انعكاسي آلي كامل:** مشغّل اختبارات القرارات لا يعمل بنقرة واحدة (يُدار يدويًا من وحدة التحكم)، وهذا دين تقني يُنصح بسداده (سكربت يشغّله في CI).

## 3) إجراءات الاستكشاف والاسترجاع (Runbook)
1. **قبل أي تعديل على قاعدة البيانات:** لقطة نسخ احتياطي (Supabase ▸ Database ▸ Backups)، وتشغيل الترحيل داخل `begin … commit`.
2. **الواجهة:** كل تعديل في فرع مستقل ثم Pull Request. الاسترجاع الفوري: زر Revert على الطلب المدموج في GitHub، ثم يُنشر تلقائيًا خلال دقيقة تقريبًا.
3. **الترحيلات:** جميعها آمنة لإعادة التنفيذ (`if not exists`، `create or replace`). لا يوجد ترحيل يحذف بيانات.
4. **أعراض شائعة:**
   - `permission denied for function`: تنقص صلاحية `grant execute` للدالة.
   - لا تظهر أزرار الإدارة: دور المستخدم ليس `admin` أو `secretary`، أو لم يُحدَّث الكاش (Ctrl+F5).
   - فشل الاستيراد لصف: افتح عمود الرسالة في نتيجة الاستيراد.

## 4) خطة النشر والرصد
- المنصة موقع ثابت على GitHub Pages، فلا يوجد canary حقيقي. البديل: النشر في فرع، ثم الدمج، ثم التحقق بـ`curl` وفتح الموقع، والرجوع بـRevert عند الخلل.
- **المؤشرات التي يُنصح بمراقبتها:** زمن تحميل الصفحة الأولى (LCP أقل من 2.5 ث)، ونسبة أخطاء Supabase (Dashboard ▸ Reports)، وفشل الدعوات في جدول `delivery_jobs`، وأخطاء Auth.
- السجلات: Supabase ▸ Logs (API وPostgres وAuth).

## 5) قائمة قبول (يملؤها من يختبر بحساب حقيقي)
- [ ] تسجيل الدخول بكل دور (مدير، أمين سر، رئيس، عضو) وظهور الأزرار الملائمة لكل دور فقط.
- [ ] إنشاء اجتماع بمرفق عربي الاسم، وإرسال الدعوات (مرة واحدة فقط لكل عضو).
- [ ] إنشاء جهة، واستيراد Excel بـ20 صفًا فيها خطأ مقصود، وظهور نتيجة كل صف.
- [ ] صفحة الأعضاء مصنفة حسب الجهة وتفتح وتُطوى.
- [ ] الوضع الداكن على: الرئيسية، الاجتماعات، الأعضاء، القرارات، التقويم، النوافذ.
- [ ] التنقل بالوحة المفاتيح (Tab وEnter وEsc) على القائمة والنوافذ.
- [ ] الجوال (عرض أقل من 520px): لا تمرير أفقي، والأزرار قابلة للضغط.
- [ ] لا أخطاء حمراء في الكونسول بعد الدخول.
- [ ] زمن فتح الصفحة الأولى أقل من 3 ث على اتصال 4G.

## 6) تحسينات مقترحة (لم تُنفَّذ، تحتاج قرارك)
1. تجميع ملفات JS في حزمة واحدة مصغّرة (بناء في GitHub Actions): يخفض الطلبات من 30 إلى 2 ويحسّن الإقلاع البارد جدًا.
2. نشر دالة الإشعارات وربط مزوّد بريد.
3. اختبارات CI آلية تشغّل مجموعة القرارات عند كل Pull Request.
