# النسخ الاحتياطي واستعادة «ميثاق» (F-08)

الخطة المجانية في Supabase لا توفّر استرجاعًا لنقطة زمنية ولا نسخًا مجدولًا مضمونًا. هذا السكربت يملأ الفجوة من جهاز مسؤول المنصة.

## ما الذي يُنسخ
- **قاعدة البيانات:** مخطط `public` كاملًا (بنية وبيانات) في ملف `public.sql`.
- **الحسابات:** جدولا `auth.users` و`auth.identities` في `auth-users.sql`. **ملف حساس** (يحوي تجزئات كلمات المرور): يُحفظ في مكان محمي ولا يُرسل بالبريد ولا يُرفع إلى GitHub.
- **الملفات:** كل المخازن (مرفقات الاجتماعات، الهوية، غرفة البيانات…) في مجلد `storage`.

## التجهيز لمرة واحدة
1. ثبّت أدوات عميل PostgreSQL (تتضمن `pg_dump`) وأضفها إلى PATH.
2. اضبط متغيّرين بيئيين في حسابك على ويندوز (لا تكتبهما في أي ملف ولا في محادثة):
   - `MITHAQ_DB_URL`: سلسلة الاتصال من Supabase ← Project Settings ← Database.
   - `MITHAQ_SERVICE_KEY`: مفتاح `service_role` من Project Settings ← API (للملفات فقط). هذا المفتاح يتجاوز كل حماية: لا يُنشر أبدًا.

## التشغيل
```powershell
powershell -ExecutionPolicy Bypass -File tools\backup.ps1
```
خيارات: `-OutDir D:\backups` و`-KeepDays 30` و`-SkipStorage`. يُنصح بتشغيله أسبوعيًا على الأقل، وقبل أي ترحيل كبير، ويمكن جدولته بمجدول مهام ويندوز.

## الاستعادة (في مشروع Supabase جديد أو فارغ)
1. طبّق الترحيلات 001–046 بالترتيب أو استعد `public.sql` مباشرة: `psql "$MITHAQ_DB_URL" -f public.sql`.
2. استعد الحسابات: `psql "$MITHAQ_DB_URL" -f auth-users.sql`.
3. ارفع ملفات `storage\<bucket>` إلى المخزن نفسه بالمسار نفسه (من لوحة Supabase أو CLI).
4. شغّل `select * from public.approval_gate_missing();` وتأكد أنها فارغة.

## تنبيهات
- لم يُختبر هذا السكربت على قاعدتك الحية لأنه يحتاج مفاتيح لا أطّلع عليها؛ شغّله أول مرة يدويًا وراجع حجم الملفات الناتجة، ثم جرّب الاستعادة على مشروع تجريبي قبل الاعتماد عليه.
- لا يُشغَّل من GitHub Actions: المستودع علني، ومخرجات الـ Actions قد تُسرَّب.
