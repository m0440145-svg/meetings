# مقترح تصميم بنرات الصفحة الرئيسية — منصة الاجتماعات (جمعية الإحسان)

مقترح تصميمي وتقني وتسويقي، مبني على ما نُفِّذ في الموقع فعلًا (`landing.js` و`banners-admin.js`) ومحدِّد لما ينقص. الأرقام التقنية (تباين، أحجام) محسوبة أو قياسية؛ وأرقام الأداء والتحويل **أهداف مقترحة لا نتائج مقاسة**، لأن الموقع لم يُنشر بعد.

> **تنبيه صريح:** لا أستطيع إنتاج ملفات Figma أو Adobe XD من هنا. التسليم أدناه (مكوّنات وأسماء وأبعاد) مواصفات جاهزة لفريق التصميم ليبنيها، والموقع الحي يصلح مرجعًا مرئيًا يُستورد إلى Figma بمكوّن إضافي لاستيراد HTML.

---

## 1) الهدف وترتيب الأولويات

الصفحة الرئيسية للزائر غير المسجل في منصة **مغلقة للأعضاء**، فالزائر الغالب عضو يريد الدخول لا عميل يحتاج إقناعًا. لذلك تختلف الأولويات عن موقع تسويقي:

| الأولوية | نوع البنر | الغرض | مثال | CTA |
|---|---|---|---|---|
| 1 | **تحويل (دخول)** | أن يدخل العضو بأقل احتكاك | «اجتماعاتك ومحاضرك في مكان واحد» | تسجيل الدخول |
| 2 | **إعلان وظيفي** | إبلاغ بحدث عاجل يخص الأعضاء | «الجمعية العمومية يوم …» / «تحديث أمني: فعّل التحقق الثنائي» | اطّلع على التفاصيل |
| 3 | **تعريف** | الهوية: الأهداف والرؤية | «حوكمة موثّقة وشفافة» | تعرّف على أهدافنا |
| 4 | **موسمي/ترويجي** | مناسبات الجمعية | رمضان، العيد، اليوم الوطني، يوم التأسيس، حملات | شارك / تبرّع (إن وُجد رابط) |

**قاعدة الترتيب:** أول شريحة دائمًا الأعلى أولوية (تحويل أو إعلان عاجل)، لأن كثيرين لا يتجاوزون الشريحة الأولى. بنر واحد فعّال لكل غرض، وبحد أقصى **5 شرائح**.

## 2) الأحجام والاستجابة

نسبة الحاوية الحالية 8:3 (2.67:1). المقترح اعتماد **ثلاث نسخ بقصّ مُوجَّه فنيًا** (Art direction) لا قصّ تلقائيًا:

| الشاشة | حاوية العرض | الصورة @1x | الصورة @2x (Retina) | النسبة | وزن أقصى (WebP) |
|---|---|---|---|---|---|
| **سطح مكتب** ≥ 1100 | حتى 1920 | **1920×720** (مدى مقبول 600–800 ارتفاعًا) | 3840×1440 | 8:3 | @1x ≤ 180 ك.ب · @2x ≤ 350 ك.ب |
| **لوحي** 700–1099 | حتى 1024 | **1024×420** | 2048×840 | 2.44:1 | @1x ≤ 90 ك.ب · @2x ≤ 180 ك.ب |
| **جوال** < 700 | حتى 430 | **375×200** (صورة فقط) | 750×400 | 1.88:1 | @1x ≤ 40 ك.ب · @2x ≤ 70 ك.ب |

**ملاحظة مهمة عن الجوال:** مقاس 375×200 يتسع لصورة فقط، لا لعنوان ونص وزر معًا فوقها (النص سيصغر ويفقد القراءة). التوصية:
- **جوال: صورة 375×200 في الأعلى، والنص والـCTA في بطاقة أسفلها** (تباين مضمون، لا حاجة لطبقة داكنة)؛ أو
- إبقاء النص فوق الصورة بارتفاع 340px كما هو حاليًا مع صورة 750×680 @2x.

**منطقة آمنة (Safe zone):**
- الصفحة RTL: ضع النص في **الـ 55% الأيمن**، والعنصر البصري (الشخص/الرمز) في الـ 35% الأيسر. هامش 5% من كل جهة لا يوضع فيه نص.
- ملف التصميم يحمل **نقطة تركيز** (Focal point) ويُعلَّم عليها لتبقى ظاهرة عند القصّ.

## 3) الهيكل البصري وتسلسل المعلومات

```
┌──────────────────────────────────────────────────────────┐
│ [عدّاد 01/03]                                            │
│        ░ الشكل البصري (35%)  │  كلمة صغيرة (Kicker)       │ ← 1) تصنيف قصير
│                              │  عنوان رئيسي (≤ 8 كلمات)    │ ← 2) الرسالة
│                              │  شرح (سطران، ≤ 120 حرفًا)   │ ← 3) السبب
│                              │  [ زر CTA رئيسي ]           │ ← 4) الفعل
│ ─────── شريط تقدم ───────────────────────────────────────│
└──────────────────────────────────────────────────────────┘
```
- **تدرّج الأحجام:** العنوان 32–40px / الشرح 16–18px / الكلمة الصغيرة 13px. الجوال: 24 / 15 / 12.
- **حدود النص:** عنوان ≤ 80 حرفًا، شرح ≤ 200 حرف (هذه حدود حقول لوحة الإدارة)، سطران كحد أقصى للشرح.
- **التباين:** نص ≥ 4.5:1 دائمًا فوق صورة أو تدرّج. الطريقة: طبقة داكنة متدرجة (من 92% إلى 35% شفافية) من جهة النص، أو بطاقة معتمة، **لا يوضع نص على منطقة مزدحمة من الصورة**.
- **الشبكة والفراغ:** 12 عمودًا، النص يشغل 6–7 أعمدة، فراغ لا يقل عن 24px بين العنوان والشرح و20px قبل الزر. عنصر بصري واحد فقط لكل بنر.
- **عدد العناصر:** عنوان واحد + CTA واحد. لا قوائم ولا أكثر من زر رئيسي.

## 4) الأسلوب البصري والهوية

| الدور | اللون | الاستخدام | التباين المحسوب |
|---|---|---|---|
| الأساسي (زينة وأشكال) | `#cf6028` | تدرجات، عناصر كبيرة | 3.9:1 على الأبيض (نص كبير فقط) |
| الأساسي للنص والأزرار | **`#a8461a`** | نص CTA، روابط | **5.9:1** على الأبيض |
| الثانوي | `#f18927` | تمييز، شريط التقدم | 6.2:1 على الداكن |
| الداكن للخلفيات | `#2b211c` | تدرج البنر | نص `#f9f4ee` عليه 14:1 |
| الدافئ | `#f9f4ee` | خلفية الصفحة | نص `#3a332f` عليه 11.3:1 |
| الرمادي الدافئ `#afa5a2` | للخطوط والزينة فقط | **لا يُستخدم لنص** (2.4:1) |

- **الخطوط:** خط عربي مقروء بأوزان 400/600/800 (Tajawal أو IBM Plex Sans Arabic، يُستضاف محليًا مع `font-display:swap`). لا تتجاوز عنصرًا بخطين.
- **الصور الفوتوغرافية:** لقطات حقيقية لعمل الجمعية (اجتماعات، مستفيدون بموافقة كتابية)، إضاءة دافئة، عمق ميدان خفيف، **بلا نصوص مدمجة في الصورة** (تُكتب النصوص بالحاسوب لتبقى مقروءة وقابلة للترجمة والقراءة الآلية). تجنّب صور المخزون العامة التي تبدو مصطنعة.
- **الرسوم التوضيحية/SVG:** أسلوب خطي بسيط بألوان الهوية للمواضيع المجرّدة (حوكمة، أمان، توثيق). أيقونات SVG بسماكة خط 2px وزوايا مستديرة، بحجم 24/32/48.
- **حماية الخصوصية:** لا وجوه أعضاء أو مستفيدين دون إذن مكتوب؛ لا لقطات شاشة لبيانات حقيقية.

## 5) الدعوات إلى الإجراء (CTA)

- **الصياغة:** فعل + نتيجة، من 2 إلى 4 كلمات، ≤ 25 حرفًا:
  - تحويل: «سجّل دخولك» · «ادخل إلى اجتماعاتك»
  - إعلان: «اطّلع على التفاصيل» · «سجّل حضورك»
  - تعريف: «تعرّف على أهدافنا»
  - تجنّب: «اضغط هنا» · «المزيد» وحدها.
- **الحجم:** ارتفاع 48px سطح المكتب و44px جوال، عرض أدنى 120px، **هدف لمس ≥ 44×44px**، حشو أفقي 24px، نص 15–16px بوزن 800.
- **اللون:** زر أبيض بنص `#a8461a` فوق الداكن (التباين 5.9:1)، أو `#a8461a` بنص أبيض فوق الفاتح. زر واحد رئيسي لكل بنر، والثانوي رابط نصي.

| الحالة | الشكل |
|---|---|
| Default | خلفية بيضاء، نص `#a8461a`، ظل خفيف |
| Hover (200ms) | ارتفاع 2px + ظل أعمق، لا تغيّر لون النص |
| Focus-visible | حلقة 3px `#f18927` بإزاحة 2px (مرئية فوق الخلفيتين الفاتحة والداكنة) |
| Active | تصغير 0.98 |
| Disabled | غير مستخدم (لا زر معطّل في بنر) |
| Loading | غير مستخدم (الزر رابط) |

## 6) الحركة والأنيميشن

| العنصر | الحركة | المدة/المنحنى |
|---|---|---|
| تبديل الشريحة | تلاشي (Fade) | 400–600ms، `ease` |
| دخول النص | انزلاق 22px + تلاشٍ بتتابع 80–120ms | 400ms، `cubic-bezier(.2,.7,.2,1)` |
| Hover/Focus للأزرار | رفع/ظل | 200ms |
| الخلفية (Ken Burns) | تقريب ≤ 8% | 16–20s، زخرفي فقط |
| التبديل التلقائي | كل 6–8 ثوانٍ | يتوقف عند المرور/التركيز/خارج الشاشة/إخفاء التبويب |

**قواعد عدم الإزعاج:** خصائص `transform` و`opacity` فقط (لا `width/top`)، لا وميض يزيد عن 3 مرات في الثانية، زر **إيقاف/تشغيل** ظاهر (متطلب WCAG 2.2.2)، احترام `prefers-reduced-motion` (تُلغى كل الحركة ويبدأ البنر ثابتًا)، لا صوت ولا فيديو تلقائيين. **نصيحة:** كل حركة زخرفية زائدة تضر بالجدية؛ البدء بأقل قدر ثم الزيادة.

## 7) الوصولية والأداء

**الوصولية (WCAG 2.2 AA):**
- نص مكتوب بالحاسوب لا داخل الصورة؛ الصور الزخرفية `alt=""`، والمعلومية (مثل شعار أو مخطط) بنص بديل وصفي ≤ 125 حرفًا.
- تباين ≥ 4.5:1 للنص العادي و≥ 3:1 للنص الكبير وحدود الأزرار.
- `aria-roledescription="carousel"` وتسمية كل شريحة «1 من 3»، والشرائح غير الظاهرة `aria-hidden` وعناصرها خارج ترتيب التبويب.
- تشغيل كامل بلوحة المفاتيح (Tab، Enter، أسهم)، وهدف لمس ≥ 44px.
- لا معلومة تُنقل باللون وحده.

**الأداء (ميزانية لكل بنر):**
- **LCP ≤ 2.5s** (الصورة الأولى هي عادة عنصر LCP): تُحمَّل بأولوية (`fetchpriority="high"`، بلا `loading="lazy"`)، والبقية `lazy` تُحمَّل قبل ظهورها بشريحة.
- WebP أو AVIF للصور، SVG للأيقونات والرسوم، **لا GIF**. الأبعاد `width/height` ثابتة لتفادي **CLS ≤ 0.1**.
- `srcset` + `sizes` + `<picture>` للنسخ الثلاث، وضغط جودة 70–78%.
- إجمالي وزن البنرات فوق الطيّ ≤ **300 ك.ب** للجوال و≤ **500 ك.ب** للمكتب.
- لا مكتبات خارجية للسلايدر (المنفَّذ حاليًا بلا مكتبات).

## 8) التجزئة والتخصيص

منصة مغلقة تعني **زوارًا قليلين ومعروفين**، فالتخصيص الدقيق غير مجدٍ والتتبع الواسع غير مناسب. يُقترح بسيط ومتوافق مع الخصوصية:

| الشريحة | القاعدة | المحتوى |
|---|---|---|
| **زائر جديد** | لا وجود لعلامة `ehsan_seen` في المتصفح | تعريف قصير بالمنصة وكيف يحصل على حساب (إن كان التسجيل بالدعوة: «تواصل مع أمين السر») |
| **عائد** | العلامة موجودة | «سجّل دخولك» أولًا ثم الإعلانات |
| **موسمي** | نافذة تاريخ (بدء/انتهاء) | رمضان، العيد، يوم التأسيس (22 فبراير)، اليوم الوطني (23 سبتمبر)، بداية العام الهجري، الجمعية العمومية |
| **بحسب الجهاز** | عرض الشاشة | قصّ الصورة المناسب |

- العلامة تُخزَّن **محليًا** (localStorage) فقط، بلا تتبع عبر المواقع ولا بيانات شخصية. إن أضفتم تحليلات فتحتاجون **إشعار خصوصية وموافقة** إن شمل المستخدمين في الاتحاد الأوروبي أو وفق نظام حماية البيانات الشخصية في المملكة.
- **المنفَّذ حاليًا:** الجدولة بتاريخ بدء وانتهاء وترتيب وتفعيل. **غير منفَّذ بعد:** حقل «الجمهور» (جديد/عائد/الكل).

## 9) الاختبار والقياس

**المؤشرات:**
| المؤشر | التعريف | هدف أولي مقترح |
|---|---|---|
| ظهور الشريحة | `banner_impression` (ظهرت ≥ 1s وبنسبة ≥ 50%) | — |
| CTR | نقرات CTA ÷ ظهور | 4–8% للتحويل، 2–4% للتعريف |
| تحويل الدخول | دخول ناجح ÷ زيارات الصفحة | يُقاس أولًا ليكون أساسًا |
| LCP | من Core Web Vitals | ≤ 2.5s |
| CLS / INP | استقرار وتفاعلية | ≤ 0.1 / ≤ 200ms |
| الإيقاف اليدوي | `banner_pause` | مؤشر إزعاج؛ ارتفاعه يعني حركة مزعجة |

**أحداث Analytics (مقترحة):** `banner_impression` · `banner_click` · `banner_cta_login` · `banner_pause` · `banner_next/prev` · `banner_dot`. المعاملات: `banner_id`، `position` (1–5)، `variant`، `audience` (جديد/عائد)، `breakpoint`، `campaign`. يُفضَّل تخزينها في جدول Supabase خاص بك (مجمّع ومجهول) بدل خدمة طرف ثالث.

**خطة A/B (واقعية لحجم زيارات صغير):**
- غير الشيء الواحد في كل اختبار: العنوان، أو نص CTA، أو صورة أو رسم.
- قاعدة تقريبية: لرصد تحسن نسبي 20% في CTR أساسه 10% يلزم **نحو 3600 مشاهدة لكل نسخة**. إن كانت زيارات الموقع بضع مئات أسبوعيًا فالاختبار الإحصائي غير عملي.
- **البديل المقترح:** تدوير النسخ بالتناوب أسبوعيًا (Sequential)، وقبول التغيير فقط إن كان الفرق كبيرًا ومتكررًا، مع اختبار قابلية استخدام مع 5 أعضاء فعليين (وقت للعثور على زر الدخول، فهم الرسالة).
- مدة الاختبار لا تقل عن أسبوعين كاملين، ولا يُنهى مبكرًا عند أول فرق.

## 10) التسليم والمواصفات

**مكوّنات Figma المطلوبة (تُبنى بالتسمية التالية):**
```
Banner / Hero / {Desktop|Tablet|Mobile} / {Conversion|Announcement|Identity|Seasonal}
Banner / Controls / {Arrows|Dots|Pause|Progress}
Banner / CTA / {Primary|Link} / {Default|Hover|Focus|Active}
Tokens: color/*, type/*, space/4-8-12-16-24-32-48, radius/12-20-24, shadow/1-2
```
المتغيرات (Variants): الاتجاه RTL، عدد الشرائح 1–5، بصورة/بلا صورة، ثيم داكن/فاتح.

**الأصول ونظام التسمية:**
```
assets/banners/{campaign}/{campaign}_{lang}_{breakpoint}_{W}x{H}@{1x|2x}.{webp|avif}
مثال: assets/banners/general-assembly-2027/general-assembly-2027_ar_desktop_1920x720@2x.webp
أيقونات: assets/icons/{name}_{24|32|48}.svg      ·      مصدر التصميم: /design/banners/{campaign}.fig
```
**حزمة كل بنر:** 3 نسخ × 2 دقة = 6 ملفات WebP + صورة احتياطية JPG (للقصور) + نص بديل + بيانات الحقول.

**بيانات البنر في لوحة الإدارة (المنفَّذة والمقترحة):**
| الحقل | الحالة |
|---|---|
| العنوان ≤ 80، النص ≤ 200، رابط https، نص الزر ≤ 30 | منفَّذ |
| صورة (رابط أو رفع ≤ 2 م.ب)، الترتيب، التفعيل، البدء/الانتهاء | منفَّذ |
| صور مخصصة للوحي والجوال (`image_tablet`, `image_mobile`) و`srcset` | مقترح |
| الجمهور (جديد/عائد/الكل) | مقترح |
| وسوم الحملة `campaign` للقياس | مقترح |
| نص بديل `alt` للصورة المعلوماتية | مقترح |

## 11) ما نُفِّذ مقابل المقترح

| البند | الحالة |
|---|---|
| بنر متحرك بلا مكتبات، تحكم يدوي من لوحة المدير، جدولة تاريخية | ✅ منفَّذ |
| تباين مدروس، إيقاف/تشغيل، لوحة مفاتيح، تقليل الحركة، توقف خارج الشاشة | ✅ منفَّذ |
| حركة دخول متتالية، عدّاد وشريط تقدم، تقريب خلفية | ✅ منفَّذ (قد تحتاج تخفيفًا لجدية الموقع) |
| صورة واحدة لكل شريحة بنسبة 8:3 | ⚠️ قائم لكنه لا يعالج الجوال بصورة مخصصة |
| `srcset`/`<picture>` ونسخ لوحي/جوال/@2x | ❌ مقترح |
| تخصيص جديد/عائد وموسمي | ❌ مقترح (الموسمي ممكن الآن بالتاريخ يدويًا) |
| أحداث التحليلات وجدول القياس | ❌ مقترح |
| ملفات Figma | ❌ يحتاج مصمم |

## 12) خطة التنفيذ والمدة

| المرحلة | المخرجات | المدة |
|---|---|---|
| 1. تحديد المحتوى والصور | قائمة البنرات، نصوص معتمدة، جلسة تصوير أو اختيار صور | 3 أيام |
| 2. تصميم Figma | مكوّنات + 3 مقاسات + نموذج تفاعلي | 4 أيام |
| 3. تطوير الجزء المتبقي (`<picture>`، الجمهور، الأحداث) | حقول جديدة وترحيل SQL | 3–4 أيام |
| 4. اختبار وصولية وأداء | Lighthouse، قارئ شاشة، أجهزة حقيقية | 2 يوم |
| 5. إطلاق وقياس أسبوعين | تقرير مؤشرات وقرار التعديل | 2 أسبوع |

**الأولوية المقترحة (أعلى عائد وأقل جهد):** (1) صور مخصصة للجوال مع `<picture>` ← (2) حقل الجمهور جديد/عائد ← (3) أحداث القياس الأربعة الأساسية ← (4) بقية الحركات تُخفَّف أو تبقى حسب انطباع المستخدمين.
