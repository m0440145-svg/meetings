## الحكم

## نطاق الفحص
راجعت قائمة المستودع كاملة: HTML وCSS وJavaScript دون خادم تطبيق داخل المستودع، 13 ملفًا نصيًا غير فارغ وملف .nojekyll فارغ. الاتصال Supabase Auth/Postgres/Storage/Realtime/Edge Functions. لا package أو اختبارات أو migrations أو نسخ من دوال Edge كانت متعقبة عند بدء الفحص.

فُحصت قاعدة المشروع المطابق لعنوان supabase-config.js قراءةً فقط: 31 جدولًا عامًا عليها RLS، و71 سياسة في public/storage، ودالتا تخزين خاصتان (meeting-files وsignatures)، وثلاث دوال Edge منشورة. وجد حساب واحد ولا اجتماعات ولا محاضر وقت الفحص. لا فروع اختبار Supabase قائمة. لم تُقرأ كلمات مرور أو مفاتيح مزودين ولم تُرسل رسائل ولم تُغيّر بيانات.

## تغييرات هذه المرحلة
إضافة أدوات بناء نسخة اختبار ترفض عنوان قاعدة الإنتاج والمفاتيح السرية، واختبارات تلقائية لها ولصلاحية صياغة السكربتات، وCI لا ينشر. لا تعديل للواجهات أو CSS أو بيانات الإنتاج. أداة البناء ليست بيئة اختبار عاملة حتى يُوفر مشروع Supabase مستقل.

## خطة المراحل وبوابات الانتقال
1. الفحص والتوثيق وأدوات عزل الاختبار: هذه المرحلة.
2. أخذ schema baseline من الإنتاج إلى نسخة معزولة، حفظ migrations، إصلاح التفويض والتخزين، اختبار السماح والمنع لكل دور ولجنتين. لا تطبيق SQL غير مجرّب على الإنتاج.
3. إكمال دورة الاجتماع بمعاملات/RPC، الحضور والنصاب والأصوات والمحاضر والإصدارات والقرارات. ترحيل البيانات بإضافات لا حذف، مع نسخة احتياطية والتحقق من الأعداد والروابط وخطة تراجع.
4. نقل الأدوات المحلية مع معاينة ترحيل واختيار السجلات والتحقق من الحفظ قبل أي تنظيف محلي. لا رفع تلقائي لبيانات جهاز مشترك إلى حساب آخر.
5. دمج مزودي الإرسال وParq، اختبار جهات استقبال مخصصة، نسخ احتياطي واسترجاع معزول، اختبار قبول كامل.
6. مراجعة ثم نشر محسوب. منع الدمج إلى main حتى اكتمال اختبار قاعدة البيانات والتكاملات المطلوبة. وظائف المورد غير المجهز تبقى واضحة وغير مفعلة.

## قرار الاستضافة الأولي
الإبقاء على GitHub Pages للواجهة وSupabase للخلفية هو الأقل تغييرًا للبنية الحالية. لا حاجة مثبتة إلى نقل Railway الآن؛ سيكون نقلًا معماريًا يحتاج خطة مستقلة إذا ظهر متطلب تشغيل لا تلبيه الدوال الحالية. هذا قرار ملاءمة بنيوية لا مقارنة أسعار.

## ما يحتاج إعدادًا خارجيًا
مشروع Supabase اختبار مستقل (لم يُنشأ بعد)، بيانات مزودي البريد وWhatsApp في مخزن أسرار فقط، وعقد API فعلي ومفاتيح Parq، ووجهة نسخ احتياطية معتمدة. لا يُعد أي تكامل جاهزًا قبل وجود معرّف إرسال/نتيجة فعلية واختبار استرجاع.

لا يتضمن هذا التقرير العام تفاصيل الملاحظات الأمنية الحساسة؛ لا ينبغي نشر خطوات استغلال إعدادات الإنتاج في مستودع عام.
